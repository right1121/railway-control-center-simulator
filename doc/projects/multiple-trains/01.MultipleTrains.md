# Milestone 3: 複数列車プロジェクト概要

## 目的

Milestone 3 では、Simulation Core と Departure Permission の前提を維持したまま、複数列車を同一シミュレーション内で安全に運用できるようにする。  
主眼は「固定閉塞が複数列車でも破綻しないこと」であり、見た目や演出は対象外とする。

## 背景

Milestone 1〜2 で以下は成立している前提とする。

- `Tick(dt)` ベースの決定論的な進行
- 固定閉塞（1ブロック1列車）不変条件
- 駅境界 API（`IsAtBoundary`, `TrainStationAtBoundary`）
- 終端挙動（`PendingTurnback`）
- 駅単位の出発許可（`POST /api/v1/simulation/permission`）

Milestone 3 はこの前提を壊さず、列車追加と列車間競合を扱う段階。

## スコープ

- Domain:
  - 列車追加時の入力検証と初期配置ルールを実装する
  - 複数列車 `Tick` での更新順序を決定論的に固定する（例: `TrainID` 昇順）
  - 同一ブロックへの同時進入競合を安全に処理し、衝突を防止する
- Application (UseCase):
  - 列車追加ユースケースを追加する
  - 既存 Simulation DTO の列車配列順序を安定化する
- Presentation (HTTP):
  - 列車追加 API を追加する
  - 入力不正 / 未存在ブロック / 競合を分類して返す
- Test:
  - 2列車以上での閉塞動作、競合処理、決定論の回帰テストを追加する
  - 既存の終端挙動・出発許可・単一列車テストが回帰しないことを確認する
- Documentation:
  - 仕様変更点を `AGENTS.md` と関連文書へ同期する

## 非スコープ

- WebSocket 配信（Milestone 5）
- 自動 Tick（サーバ主導の時間進行）
- ダイヤ計算・経路探索・優先制御
- ゲーム的要素（スコア、ランダム挙動）

## 振る舞い要件（Milestone 3）

- 列車追加時は以下を満たさない入力を拒否する
  - `trainId` 重複
  - 初期 `blockId` が占有済み
  - `progress` が `0.0..1.0` の範囲外
  - 存在しない `blockId`
  - `speed <= 0`
- `Tick(dt)` は `dt <= 0` を拒否し、複数列車でも決定論的に同一結果を返す
- 1ブロック同時占有は最大1列車を厳守する
- 列車が次ブロックへ進入する際、次ブロック占有中なら境界で待機する
- 同 Tick 内で同一ブロックへの進入候補が複数ある場合、事前に定義した順序で1列車のみ進入を許可し、他列車は待機する
- 占有遷移は `release(from)` と `occupy(to)` を対で扱い、二重登録を起こさない

## API 概要（初版）

- Endpoint: `POST /api/v1/simulation/trains`
- Request:
  - `trainId` (string)
  - `blockId` (string)
  - `progress` (number, `0.0..1.0`)
  - `direction` (`"Up"` / `"Down"`)
  - `speed` (number, `> 0`)
- Response:
  - 追加後の Simulation DTO（`trains[]` 順序は固定）
- Error:
  - `400`: 入力不正（ID 形式、範囲外 progress、`speed <= 0` など）
  - `404`: 指定 `blockId` が存在しない
  - `409`: `trainId` 重複、または初期占有競合
  - `500`: 想定外エラー

## テスト要件

- 2列車が前後同方向で走行し、後続が前列車に追突しない
- 先行列車が次ブロックを解放した次 Tick で後続が進入できる
- 同一 Tick で同一ブロック進入競合が発生しても結果が決定論的に固定される
- 列車追加バリデーション（重複 ID、占有競合、無効 progress、無効 speed、不正 block）を網羅する
- DTO の `trains[]` 順序が毎回安定していることを保証する

## 完了条件

- 2列車以上で固定閉塞が正しく機能し、追突が発生しないことをテストで固定できる
- 列車追加 API が仕様どおりの正常系・異常系を返す
- 既存 Milestone 1/2 テストが回帰しない
- コード・テスト・ドキュメントが同一仕様を示す

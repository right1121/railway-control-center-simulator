# 鉄道管制訓練シミュレーター MVP 要件

## 1. 目的

本プロジェクトの目的は、**鉄道の運行管理者（管制員）向け訓練用シミュレーション基盤**を構築することです。  
ゲームではなく、業務訓練を想定した正確性重視のシステムを目指します。

## 2. 前提条件（スコープ）

### 技術前提

- 完全ブラウザ型
- Go バックエンド
- HTTP API（WebSocket は将来対応）
- 永続化なし（InMemory）

### 機能制約

- 2D のみ（描画は外部）
- 固定路線（直線）
- 固定閉塞
- 列車速度は定数
- 進捗（`0.0-1.0`）を保持
- 複数管制員を想定
- 外部連携なし
- オフライン不要

## 3. シミュレーションモデル

### 3.1 路線構造

- 路線は直線
- 駅は「ブロックの端（境界）」
- ブロックは駅と駅の間

```text
S0 == B0 == S1 == B1 == S2 == B2 == S3
```

### 3.2 列車

列車は以下の状態を持ちます。

- `currentBlock`
- `progress`（`0.0-1.0`）
- `direction`（`Up` / `Down`）
- `speed`（定数）

列車は「駅に存在する」という状態を持たず、駅は境界イベントとして扱います。

### 3.3 駅ロジック

駅境界到達時に、以下を満たす必要があります。

- 到着イベント発生
- 次ブロックに入るには出発許可が必要
- 次ブロックが占有されていないこと

### 3.4 固定閉塞の不変条件

- `1ブロック = 1列車`
- 占有ブロックへ進入不可
- 出発許可なしで駅発不可
- 終端駅で停止

## 4. 時間モデル

- シミュレーションは `Tick(dt)` でのみ進行
- 自動時間進行なし
- Domain 内で `time.Now()` 使用禁止

## 5. アーキテクチャ要件

- `Domain / Application / Infrastructure / Presentation` を分離
- Repository interface は Domain 層に置く
- UseCase は DTO を返す
- Domain は外部技術を知らない
- DI コンテナで依存注入

## 6. MVP 定義

以下を「完成」とみなす最小機能とします。

### MVP-1: セッション管理

- 管制員参加
- 管制員退出
- セッション状態取得

### MVP-2: 路線定義

- 直線路線
- 駅数固定
- ブロック数 = 駅数 - 1

### MVP-3: 列車配置

- 列車追加
- 初期ブロック占有登録

### MVP-4: Tick

- 時刻更新
- 進捗更新
- 駅境界判定
- 出発許可チェック
- 固定閉塞チェック
- 占有更新

### MVP-5: 出発許可制御

- 駅ごとの許可 ON/OFF

## 7. MVP に含めないもの

- 分岐路線
- ポイント制御
- 番線
- 列車ダイヤ
- 加減速
- 停車時間
- リプレイ
- 永続化
- WebSocket 同期

## 8. 成功条件

以下を満たせば MVP 成功です。

- 単一セッションで列車が進行する
- 駅で止まる
- 許可を出すと発車する
- 占有ブロックへ侵入できない
- 複数管制員でも状態が壊れない

## 9. 本質

この MVP は、**「固定閉塞 + 境界駅 + 時間進行」**という最小だが拡張可能なコアを作ることが目的です。  
これが安定すれば、以下へ自然に拡張できます。

- WebSocket 同期
- 分岐
- ダイヤ
- 訓練シナリオ

# Milestone 2: Departure Permission プロジェクト概要

## 目的

Milestone 2 では、Simulation Core に「管制による出発許可」を導入する。  
列車は駅境界に到達しても、対象駅の許可がなければ発車できない状態を標準動作にする。

## 背景

Milestone 1 で以下は成立している前提とする。

- `Tick(dt)` ベースの決定論的な進行
- 固定閉塞（1ブロック1列車）不変条件
- 駅境界 API（`IsAtBoundary`, `TrainStationAtBoundary`）
- 終端挙動（`PendingTurnback`）

Milestone 2 はこの前提を壊さず、停止理由に「許可待ち」を追加する段階。

## スコープ

- Domain:
  - 駅単位の出発許可状態を `SimulationState` で保持
  - 駅境界で許可がない場合は停止し、次ブロックへ遷移しない
  - 許可がある場合のみ次 `Tick` で進行可能
- Application (UseCase):
  - 出発許可 ON/OFF の更新ユースケースを追加
  - Simulation 取得 DTO に必要な許可情報を反映
- Presentation (HTTP):
  - `POST /api/v1/simulation/permission` を追加
  - 不正入力・存在しない駅・不正状態のエラーを分類して返す
- Test:
  - 許可 OFF 停止 / 許可 ON 進行 / 許可切替の回帰テスト
  - 既存の占有不変条件・決定論が壊れないことを確認
- Documentation:
  - `AGENTS.md` と関連文書に Milestone 2 仕様を同期

## 非スコープ

- 列車追加 API（Milestone 3）
- WebSocket 連携（Milestone 5）
- ゲーム的要素（スコア、ランダム挙動）

## 振る舞い要件（Milestone 2）

- 列車が駅境界にいるとき、対象駅の許可が OFF ならその `Tick` では進まない
- 許可が ON に変更された後、次の `Tick` から進行できる
- 許可の有無に関わらず、占有済み次ブロックへの進入は禁止
- `dt <= 0` の拒否、更新順序固定、DTO 順序固定の決定論要件は維持する

## API 概要（初版）

- Endpoint: `POST /api/v1/simulation/permission`
- Request:
  - `stationId`
  - `allowed` (`true` / `false`)
- Response:
  - 更新後の許可状態、または Simulation DTO（実装方針に合わせて統一）
- Error:
  - `400`: 入力不正
  - `404`: 駅が存在しない
  - `409`: 状態競合（必要時）

## 完了条件

- 駅境界で「許可なしでは動かない」「許可で動く」がテストで固定される
- 既存の Tick / 占有 / 終端挙動テストが回帰しない
- HTTP 経由で許可操作ができ、期待するエラー分類で応答する
- コード・テスト・ドキュメントが同一仕様を示す

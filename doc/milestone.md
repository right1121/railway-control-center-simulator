# 🎯 MVPゴール（再定義）

## 最終的に到達すべき状態

- 直線路線
- 固定閉塞
- 列車が `Tick` で進む
- 駅境界で停止する
- 許可があれば発車する
- 占有ブロックへ侵入しない
- HTTP で操作できる

これが「訓練用コア」です。

## 🧭 マイルストーン設計

### 🟢 Milestone 1: Simulation Core 安定化

**目的**  
シミュレーションが壊れない状態を作る。

**タスク**

- `SimulationState` の仕様固定
- `Tick` の挙動をテストで完全固定
- 終端挙動を明確化（折返し or 停止）
- ブロック占有の不変条件テスト強化
- 駅境界判定 API を追加（`progress == 0/1` 依存を隠す）

**完了条件**

- `Tick` のユースケースが壊れない
- 進行・停止・占有の動作がテストで保証される

### 🟡 Milestone 2: Departure Permission 実装

**目的**  
「管制」という概念を入れる。

**タスク**

- 駅単位の許可状態を `SimulationState` に追加
- 出発許可がない場合、境界で停止
- 許可 ON で次 `Tick` で進行
- HTTP API 追加
  - `POST /api/v1/simulation/permission`
- 許可 ON/OFF テスト

**完了条件**

- 駅で止まり、許可で動く
- 訓練として意味が出る

### 🟠 Milestone 3: 複数列車

**目的**  
固定閉塞の意味を持たせる。

**タスク**

- 列車追加 API
- 占有衝突テスト
- 列車同士のブロック競合処理

**完了条件**

- 2列車で閉塞が機能する
- 後続列車が前列車に追突しない

### 🔵 Milestone 4: HTTP整理 & 安定化

**目的**  
API として壊れにくくする。

**タスク**

- エラー分類（`400/404/409/500`）
- DTO 安定化
- `README` 整備
- `AGENT.md` 整合性修正

**完了条件**

- API として一貫性がある
- 仕様がコードと一致

### 🟣 Milestone 5: リアルタイム化（任意）

**目的**  
複数管制員の共有。

**タスク**

- WebSocket 導入
- 状態ブロードキャスト
- `Tick` 自動実行（サーバ主導）
